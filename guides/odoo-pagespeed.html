Why Odoo shops score low on Google PageSpeed, and how to fix it

November 2026 · Odoo 18, 19 and 20

Run an Odoo eCommerce shop through Google PageSpeed Insights on a phone and the performance score is often in the orange or red, even on a fast server. The reason is not your hosting alone: three things in a standard Odoo shop slow down what Google measures.

What PageSpeed measures

PageSpeed runs Lighthouse with a simulated mid-range phone and a slow mobile connection. The metrics that matter most:

  • First Contentful Paint (FCP): when the first text or image appears.
  • Largest Contentful Paint (LCP): when the main element appears, on a shop usually the first product photo. It is one of the three Core Web Vitals Google uses as a ranking signal; the target is 2.5 seconds or less.
  • Server response time (Time To First Byte): nothing can be displayed before the server has answered.

Cause 1: the whole stylesheet blocks the first display

Odoo sends one big stylesheet for the whole website (about 1.1 MB before compression on the demo shop). The browser waits for all of it before showing anything, although a single page uses only a small part of it.

What helps: serving first the CSS the page actually needs ("critical CSS") and loading the rest right after. On the Odoo 20 demo shop, this made the first display of the shop page go from 3.79 s to 1.75 s on mobile.

Cause 2: product photos loaded late and too large

Odoo marks every product image of the shop as lazy-loaded, including the first ones visitors see. The browser discovers them late. Phones also download large variants of the photos for small thumbnails.

What helps:

  • Upload photos at a reasonable size: a 6000 px camera photo is never needed.
  • Load the first row of products immediately and tell the browser the real display size of each image.
  • Serve images as WebP, lighter than JPEG and PNG.

On the Odoo 20 demo shop with real-size photos (2400 px), loading the first images first and at the right size took the LCP of the shop page from 12.9 s to 3.8 s on mobile, and its weight from 6.6 MB to 2.2 MB.

Cause 3: every page rendered again for every visitor

Odoo renders each page on the server for each visitor: products, prices, menus, translations. On the demo shop, the shop page takes about 165 ms of server time with one worker; on a large catalog it can be much more, and it grows with traffic.

What helps: a page cache for anonymous visitors, which must never serve a page that contains someone else's cart or session. On the demo shop the shop page went from 165 ms to 9 ms of server time.

Checks you can do today, without any module

  • Test the shop page and a product page in PageSpeed Insights, on mobile, a few times: results vary between runs.
  • Check the size of your product photos and banners; resize anything above about 2000 px.
  • Make sure your reverse proxy compresses responses (gzip or brotli) and caches static files.
  • Remove website snippets and apps you do not use: they add CSS and JavaScript to every page.
